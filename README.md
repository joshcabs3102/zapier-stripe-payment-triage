A private, custom Zapier CLI integration that automatically triages failed Stripe charges by customer Lifetime Value (LTV). It combines direct Stripe polling, Supabase PostgREST lookups, and conditional multi-channel dispatch into an atomic 2-step pipeline that runs permanently on Zapier's Free plan.

High-value accounts ($\ge \$5,000$ LTV) are immediately routed to a sales Slack channel for high-touch Account Executive recovery. Self-serve accounts ($< \$5,000$ LTV) trigger automated dunning emails via Postmark.

> [!NOTE]
> **Why this CLI architecture exists:**
> Standard Zapier visual workflows require a paid subscription to execute multi-step logic (3+ steps), branch conditionally (Paths), or receive generic HTTP hooks (Webhooks by Zapier). By packaging the lookup, scoring, and conditional notification logic into a custom Node.js action via the Zapier Platform CLI, this entire workflow consumes **exactly 2 steps (1 Trigger + 1 Action)** and requires **$0/month in third-party or platform licensing**.

## Architecture

```text
[ Step 1: Stripe Trigger (Native CLI Polling) ]
  │  Polls: GET https://api.stripe.com/v1/charges?status=failed
  │  Auth: sk_test_... (Bypasses Stripe App Marketplace merchant activation)
  ▼
[ Step 2: Custom Triage Action (triage_payment) ]
  ├── 1. Query Supabase: GET /rest/v1/customers?stripe_customer_id=eq.{id}
  ├── 2. Evaluate Account Tier: LTV >= 500,000 cents ($5,000.00)
  └── 3. Conditional Dispatch:
        ├── [LTV >= $5k] ──> Slack Webhook (Urgent AE Escalation Card)
        └── [LTV <  $5k] ──> Postmark API (Automated Dunning Email)
```

## Features

- **Free-Tier Compliant:** Respects the Zapier Free plan's hard 2-step execution limit.
- **Zero Merchant Verification Required:** Queries Stripe's charges API directly using secret keys (`sk_test_...`), bypassing the Stripe App Marketplace merchant activation paywall.
- **Floating-Point Safe:** All financial calculations use integer arithmetic representing cents (`500000` cents = `$5,000.00`).
- **Defensive Fallback Resolution:** Automatically resolves recipient email addresses from Supabase customer records if Stripe charge metadata omits billing details.
- **Automated Test Coverage:** Includes unit test suites for all logic branches using Jest with 100% offline network mocking.

## Quickstart

### 1. Clone & Install Dependencies

```sh
git clone https://github.com/your-username/zapier-stripe-payment-triage.git
cd zapier-stripe-payment-triage
npm install
```

### 2. Run Test Suite

```sh
npm test
```

### 3. Deploy to Zapier

Ensure you have the [Zapier Platform CLI](https://github.com/zapier/zapier-platform/tree/main/packages/cli) installed and authenticated:

```sh
# Validate schema and manifest
npx zapier-platform validate

# Register private integration (first-time only)
npx zapier-platform register "Stripe Failed Payment Triage"

# Deploy package
npx zapier-platform push
```

## Database Provisioning (Supabase)

Execute the following script in the **Supabase SQL Editor** to establish the `public.customers` table with Row Level Security (RLS) enabled:

```sql
-- 1. Create customers schema
CREATE TABLE public.customers (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    stripe_customer_id TEXT NOT NULL UNIQUE,
    email TEXT NOT NULL,
    lifetime_value BIGINT NOT NULL DEFAULT 0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 2. Enable Row Level Security (RLS)
ALTER TABLE public.customers ENABLE ROW LEVEL SECURITY;

-- 3. Allow read access for authenticated and anonymous API clients
CREATE POLICY "Allow public read access for triage action"
ON public.customers
FOR SELECT
TO anon, authenticated
USING (true);

-- 4. Seed sample test data
INSERT INTO public.customers (stripe_customer_id, email, lifetime_value)
VALUES
    ('cus_HIGH_VAL_001', 'buyer@acmecorp.com', 650000),   -- $6,500.00 LTV
    ('cus_LOW_VAL_002', 'developer@starter.io', 120000);  -- $1,200.00 LTV
```

## Configuration & Credentials

When connecting the integration on [Zapier](https://zapier.com), provide the following parameters:

| Parameter Key       | Description                                                | Example / Sandbox Format               |
| :------------------ | :--------------------------------------------------------- | :------------------------------------- |
| `stripe_secret_key` | Stripe Secret API Key                                      | `sk_test_...`                          |
| `supabase_url`      | Base URL of your Supabase project (no trailing `/rest/v1`) | `https://xyzcompany.supabase.co`       |
| `supabase_key`      | Supabase Anon Public API Key                               | `eyJhbGciOiJIUzI1NiIsIn...`            |
| `slack_webhook_url` | Slack Incoming Webhook URL                                 | `https://hooks.slack.com/services/...` |
| `postmark_token`    | Postmark Server API Token                                  | `POSTMARK_API_TEST` (or server token)  |

> [!TIP]
> **Testing Postmark without a verified domain:** Use `POSTMARK_API_TEST`. Postmark's production servers will validate headers and payload syntax, return an authentic `200 OK`, and simulate delivery without needing a verified company email domain.
